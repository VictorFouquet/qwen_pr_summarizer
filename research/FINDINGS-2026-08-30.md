# Research findings — 2026-08-30 (auto-researcher)

## TL;DR
The prompt-optimization loop was **inert**: `main.py` built `ChatOllama` with Ollama's
default `num_ctx=2048`, but the eval-PR groundings are 24k–38k tokens. The tool output
overflowed the window and the **system prompt (at the head) was truncated away before
generation**, so the model never saw the prompt. Three genuinely different prompts
produced **byte-identical** summaries for PR#8 and #11 — proof the prompt had no effect.

Trials 1–3 are therefore **not valid prompt experiments** (baseline 0.079; two edits
"regressed" to 0.062 — noise, not signal).

## Evidence
- Same 4439-token input → `prompt_eval_count=2050` at default vs `4439` at `num_ctx=16384`.
  Ollama default `num_ctx` = **2048**.
- Sentinel test: a system prompt saying "output only WOMBAT" is obeyed when the input
  fits, but **ignored** once the input overflows the window (model answers about the
  tail instead). `num_keep` did not rescue it.
- Grounding sizes: PR#8 ≈ 25k tok, PR#10 ≈ 24k tok, PR#11 ≈ 38k tok (model max ctx = 40960).

## Fix applied (authorized main.py change)
- Added `NUM_CTX` (default **40960**, overridable via `PR_SUMMARIZER_NUM_CTX`) and pass
  it to `ChatOllama(..., num_ctx=NUM_CTX)`.
- Added `num_ctx` to `frozen_config()` so `config_fp` records it — cleanly separating
  pre-fix trials (`f862429e07b6`) from post-fix (`90428e5efc2e`). **Re-baseline** before
  comparing.

## Hardware blocker on THIS machine (why the overnight loop was NOT run)
- **GPU:** Ollama is the **snap** package and runs **100% on CPU** — even `num_gpu=99`
  won't offload. Enabling CUDA needs a non-snap Ollama or snap reconfig = **sudo/system
  changes** the auto-researcher must not make unattended.
- **Memory:** 15 GB RAM (only ~3.2 GB free, 5 GB swap already used) and 8 GB VRAM.
  qwen3:8b (~6 GB) + a 32k–40k KV cache (~5–6 GB) fits **neither**. At the `num_ctx`
  needed to hold a PR's grounding, the KV cache spills to swap → CPU inference
  swap-thrashes for hours per PR. Running 11 trials overnight would not finish and would
  destabilize the active desktop session.

## Recommended ways to actually run it (pick one)
1. **Bigger box / working GPU:** a machine with ≥ ~12 GB free VRAM (or ≥ ~16 GB free RAM)
   runs the default `num_ctx=40960` for all three PRs. Then: re-baseline → optimize prompt.
2. **Non-snap Ollama here (needs sudo):** `curl -fsSL https://ollama.com/install.sh | sh`
   gives working CUDA on the RTX 3070 — but 8 GB VRAM still can't hold model + 40k KV, so
   pair with a smaller `PR_SUMMARIZER_NUM_CTX` and accept partial grounding.
3. **Reduce grounding** (would need a harness change beyond the prompt, so out of scope
   for the prompt-only loop): cap patch bodies so system prompt + grounding fit ~12k ctx.

## GPU brought online (userspace Vulkan)
Snap Ollama is CPU-only (empty `/var/lib/snapd/lib/gl`, no sudo) and official CUDA needs
driver ≥550 (box has 535). Solution: userspace Ollama v0.33.2 on the **Vulkan** backend,
pinned to the 3070 (`GGML_VK_VISIBLE_DEVICES=2`), reusing the snap's model blobs, on
`:11435`, with `q8_0` KV + flash-attention so a big context fits 8 GB. ~15× faster than
CPU (trial ≈ 12 min). Harness points at it via `OLLAMA_HOST` + `PR_SUMMARIZER_NUM_CTX=32768`.
At 32768, #8 (25k) & #10 (24k) fit → prompt visible; **#11 (38k) still overflows** on 8 GB
(prompt-blind, stuck at 29/70 files, 665 words — unmovable here).

## What moved the score, and what didn't
- **Coverage was the lever.** Once the prompt was visible the model was faithful and terse
  but named directories/packages/classes instead of files (cov 0.062). Telling it to name
  the actual changed files by their `FILE:` path took composite 0.058 → 0.404.
- **The model is extremely fragile to prompt wording.** Helping one PR often broke another
  (#8↔#10), and *any* text added near the grounding block collapsed coverage (trials 9,10).
- **Two anti-patterns, both confirmed live:** (1) concrete example filenames bias unrelated
  PRs (trial 7); (2) negative examples *prime* the model to emit the very tokens they forbid
  (trial 9). Prefer short, general, positive instructions.
- **#11 is unmovable on 8 GB VRAM** — its 38k grounding overflows num_ctx=32768, so its
  prompt is truncated and it's stuck (0.29). A ≥~12 GB GPU (num_ctx≥40960) would unblock it.

## OBJECTIVE CHANGE — filename-coverage was the wrong target
The v1 metric (`coverage` = fraction of changed filenames echoed) diverges from the real
job: the summarizer should write a **high-level PR body** for review, not list files.
Much of the v1 0.058→0.404 climb was the summarizer getting *worse* at its actual job
(turning prose into file lists) while the number went up — a gamed proxy. So the metric
was redefined and the v1 trail archived (`research/*_v1_coverage.*`).

## v2 metric — body_similarity (embedding vs the real PR body)
`composite = faithfulness × body_similarity × (0.7 + 0.3·brevity)`; coverage kept only as
a diagnostic. `body_similarity` = cosine(embed(summary), embed(real PR body)) via local
`nomic-embed-text`, rescaled [0.60,0.90]→[0,1]. Deterministic, local, reference-based.
Validated up front: it prefers prose over filename-lists and floors vague filler.
Config `a89bd8ec1635`. **Not comparable to the v1 numbers.**

## The biggest win: stop feeding the model noise (trial 5)
PR#11's diff was 38k tokens, ~19k of it a single design-plan markdown (lockfiles/config
were only 2%). It overflowed num_ctx=32768, its prompt truncated, and it code-dumped 665
words (body_similarity stuck 0.527). `get_pr_files` now caps each patch to 120 lines and
omits lockfile bodies: #8 25k→10.6k, #10 24k→13.3k, #11 38k→21.4k — all fit with headroom.
#11 then wrote **124 words of prose, bsim 0.527→0.972**, and brevity went 0.667→1.0
overall. Composite 0.681→0.911 with no prompt change. This solved the "#11 is VRAM-locked"
anchor in software instead of hardware.

## What we learned (v2)
- **The seed prose prompt is already a strong PR-body writer** (0.63): once you stop
  rewarding filenames, the model's natural prose matches the real body well — #10 hit
  body_similarity **1.0**.
- **The `body_similarity` metric behaves**: the prose reframe (trial 3) genuinely raised it
  (#8 0.765→0.827), confirming it tracks PR-body quality, not filename echo.
- **Faithfulness vs slashes is whack-a-mole**: the deterministic grounder flags any "A/B"
  prose pair (`BullMQ/Redis`, `console/email`) as a bogus path; suppressing them in one PR
  induces them in another. This is partly a *verifier* false-positive on legitimate prose —
  a candidate for refining the grounder (loosen `_PATH_RE` for non-path A/B pairs).
- **#11 is the anchor and is VRAM-locked**: its 38k-token grounding overflows num_ctx=32768
  on 8 GB, so its prompt is truncated, it code-dumps 665 words, and body_similarity sticks
  at 0.527 regardless of prompt. It caps the aggregate at ~0.74. A ≥~12 GB GPU unblocks it.

## v3 — agentic tools + a fixed metric, and a REAL prompt campaign
Two flaws were fixed so the prompt could finally be the lever:
1. **No hardcoded relevance.** `get_pr_files` (which dumped every patch and overflowed the
   window) was split into three tools — `list_pr_files` (table of contents, no diffs),
   `get_file_diff` (one file's diff), `read_file` — so the agent decides what to open,
   steered by the prompt. Every trial logs the agent's **tool-call trace** (which files it
   opened / skipped) so under-reading is visible.
2. **Faithfulness had to be earned.** The old precision score gave an empty/unread summary a
   free 1.0 — the "trader who never trades." Redefined as
   `grounded_specifics / (grounded_specifics + hallucinations + 2)`, with identifiers &
   endpoints (which live in diffs → require reading) weighted 1 and paths 0.3, empty → 0.
   Also stopped the grounder flagging ordinary "A/B" prose as invented paths.

With those fixed, the prompt campaign (tools & metric now frozen) — **every gain purely the
prompt, trace-verified:**

files (2/1/1 diffs) and reports grounded specifics — real reading, not bluffing. Remaining
instability is #11 (70 files), where the 8B model's faith still swings.
